# 视频与文件管理上位机系统 - 需求规格说明书

## 1. 系统概述
本系统为一个上位机应用程序，主要功能包括：**实时UDP视频流点播**、**下位机文件TCP检索与下载**、以及**本地历史文件（视频与数据库）的查看与解析**。系统采用主页面+多子页面的架构进行切换管理。

## 3. 功能详细需求

### 3.1 子页面 1：实时视频流显示
* **核心逻辑**：
    * 上位机作为 UDP 接收端，监听指定端口。
    * 动态接收下位机发送 over UDP 的图像原始数据（如 JPEG 压缩帧或 Raw 数据）。
    * 将接收到的数据流实时解码并刷新到界面的视频播放控件中。

### 3.2 子页面 2：远程文件检索与下载
* **通信协议**：TCP 协议（保证数据传输的可靠性）。
* **业务流程**：
    1.  **查询列表**：点击“查询文件”按钮 -> 上位机下发预先规定格式的查询 JSON 命令 -> 下位机响应并返回包含文件数量和名称的 JSON 报文 -> 上位机解析该 JSON。
    2.  **列表展示**：将解析出的文件名称及数量渲染到**表格（Table）**或**下拉框（ComboBox）**中，条目支持点击交互。
    3.  **文件下载**：点击某一个文件条目 -> 上位机下发“下载指定文件”的 JSON 命令 -> 下位机通过 TCP 传输该文件数据 -> 上位机接收完整数据并将其保存到本地指定路径。

### 3.3 子页面 3：本地历史文件查看
* **核心逻辑**：
    * 进入页面时，自动扫描或加载本地已下载的文件列表。
    * **.avi 文件处理**：用户点击 `.avi` 格式的文件时，系统调用内置/第三方视频播放器组件进行视频回放。
    * **.db 文件处理**：用户点击 `.db` 格式的数据库文件时，系统连接该本地数据库，读取并解析核心数据，最终以表格或图表的形式在界面上展示。

## 5. 开发注意事项（技术备忘）
1.  **多线程处理**：UDP视频流接收、TCP文件下载均属于网络耗时操作，**必须**放在子线程（Worker Thread）中处理，避免阻塞主 UI 线程导致界面卡死。
2.  **TCP 粘包与半包**：在接收下位机上传的 JSON 报文或大文件数据时，TCP 协议可能会出现粘包现象。建议在 TCP 应用层协议中加入“**帧头+帧长度+数据体**”的格式进行断包解析。
3.  **状态同步**：从子页面1切换到其他页面时，注意是否需要暂停 UDP 接收以释放 CPU 资源；从其他页面切回时再重新监听。
